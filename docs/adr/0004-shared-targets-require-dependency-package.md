# Require a shared dependency package for shared targets

Multiple instances of the same `multi_instance` package are distinct tracked identities, and dotman deliberately does not merge two instances that declare an identical target (same rendered source and destination). Identical shared targets still conflict, and the sanctioned way to share a target is to declare it once in a base package that the instances depend on.

The merge was considered and rejected because it cannot be made safe under dotman's metadata-first ownership model. Ownership compares resolved declarations, not rendered bytes, so a shared target whose source is a Jinja template over `{{ profile }}` (or whose `render`/`capture` command renders per-instance) would silently collapse to one instance's output and drop the others'. The alternative "merge as one" semantics also make ownership asymmetric: the shared target would be planned and attributed under a single deterministic instance, and `info tracked` / `list tracked targets` would show it under only one profile. A base dependency package avoids both problems by declaring the shared target once with unambiguous ownership and no implicit merging.
